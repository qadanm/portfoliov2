## The premise

Every LLM router I could find prices a request the same way: tokens multiplied by dollars per million. That is the right model for pay-as-you-go, and it is the wrong model for almost anyone who reads this site. A coding subscription is not a price list. It is a set of windows that expire, a five-hour window inside a seven-day window inside a monthly ceiling, often metered per model, sometimes split across two credit pools that draw at different rates.

A token-based router cannot see any of that. It picks the cheapest model on paper and keeps picking it while allowance you already paid for expires unused.

## What it does instead

OpenCode Smart Router models the plan rather than the token. Classification runs locally in about a millisecond, reading the structure of a prompt rather than its wording: scope, attachments, agent type, context size, recent failures. No model call is spent deciding which model to use.

Then it filters before it prices. A candidate is discarded if the plan cannot fund it, if a provider allowance is exhausted, if the task needs native image input the model lacks, or if the work sits below the intelligence floor. Refusals are recorded with their reason, so "why did it pick that" has an answer.

What remains is priced against the windows that will actually be charged, with one adjustment that matters more than any other: prepaid allowance that is about to reset is priced near its probability of being wasted. Spending a pool that expires in forty minutes is close to free, because the alternative is losing it. The discount is bounded and never reaches zero, since a pool with no headroom cannot carry the work.

## Self-healing

The month I shipped this, a live session handed me a better problem than costing.

![The router panel: the chosen model with its reasoning, the rejecting model named in the self-heal line, and the block list with its reasons.](/images/smart-router/router-panel.webp)

Rebuilt sessions put mid-session notices into the prompt as system-role messages, and the Anthropic protocol only accepts user and assistant roles. On any Claude-model provider, every turn died with `Invalid discriminator value. Expected 'user' | 'assistant' at messages.23.role`, and the host retried the identical doomed request several times before giving up. Upstream core converts notices per protocol; whether the error happens depends on which gateway a model sits behind, so the same session moved from glm to haiku and started failing.

Instead of patching the host, the router picked the problem up. Three behaviors, each with its own bad way to get it wrong:

**Repair the prompt in flight.** A context hook folds every system-role entry after the first message into a user message, for Anthropic-protocol providers only. The text is untouched; the role now matches what the wire accepts. The obvious alternative, rewriting history in the session store, would have corrupted every other model's view of the conversation. The obvious first version also folds a leading system message, which would have moved the system prompt channel and invalidated Anthropic's prompt cache on every request.

**Never retry a rejected request shape.** The failure mode is deterministic: the same 400 returns the same result, so the host's retry loop is refused on the first rejection. This took its own failure class and a classifier fix, because a deterministic 400 was being mistaken for a gateway outage and retried with backoff, which is where the wasted turns were actually coming from.

**Fail over once, and continue.** The rejecting model is held back for five minutes (its reliability record is untouched; the model is healthy, the request shape was not), the stored task re-routes to the next best candidate, the session switches when the failed turn is over, never mid-flight, and a one-line notice in the session says what was rejected. Once per prompt, guarded by prompt identity, so it can never loop. The alternative that first tempted me, failing over immediately inside the retry hook, was the exact pattern that produces "model unavailable" errors on queued steps; the codebase had already documented that live incident four days earlier.

## Four decisions that shaped it

**Eligibility runs before cost.** A cheap model that cannot serve the task is not a candidate, so it never wins on price. Filtering first also makes the refused cases explainable instead of silently expensive.

**A refusal outlives the reading that produced it.** Quota probes go stale. If a provider reported exhausted a minute ago, it stays excluded until a fresh probe clears it, rather than becoming eligible the moment the number ages out. The opposite asymmetry, where a permission expires but a refusal does not, is how a router routes into a full allowance.

**Missing quota fails closed, but only when it means something.** A probe-enabled provider with no reading yet is refused when other providers have already reported, because that is the window before the first probe where an exhausted allowance looks identical to a healthy one. A provider that is not probed at all stays allowed, because absence is how "untracked" is expressed and refusing there would break ordinary fallbacks.

**Switching is not free.** A model change discards a warm prompt cache, which costs real money. The router prefers staying put and only moves when the saving clears a margin, so quota preference cannot turn into thrash.

## Tested by breaking it

759 tests across 63 files cover classification, eligibility, quota parsing, credential discovery and its security properties, ledger accounting, pool reconciliation, cache-aware routing, premium protection, failure classification, the prompt-repair hook, and the failover path, including its caps and guards.

Tests alone prove less than they look like they do. `npm run mutate` reverts each of 62 safety properties in turn and fails if the suite still passes, which is the only check that proves a test is guarding anything. Several mutations came back vacuous during development, and each one exposed dead code that was then deleted rather than guarded.

`npm run verify` repeats the whole suite in a clean room with an empty `HOME`, so a pass cannot depend on the maintainer's config or credentials.

## Shipped as a tool, not a demo

The routing core publishes on npm as a single self-contained file with no runtime dependencies, so one line installs it into any OpenCode config:

```json
{ "plugin": ["@qadanm/opencode-smart-router"] }
```

The full experience (desktop panel, terminal commands, history import, first-run onboarding) ships through an installer that validates the source and runs the full suite before touching a config file. Installs are versioned: each one lands in its own directory and only the config pointer changes, so a running session keeps the module it already loaded. That detail is not incidental. Replacing files inside the watched plugin directory invalidates the module mid-session and empties the provider's model list, which surfaces as a model-unavailable error for a model that is perfectly healthy. I shipped that bug, found it in the logs, and rebuilt the installer around it.

The quota engine also ships standalone as `dist/allowance.js`, with no host dependency, so "when does this plan run out" is answerable outside OpenCode.
